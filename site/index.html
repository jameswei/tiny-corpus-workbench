This site describes the workbench. It does not process documents.

Purpose and workflow

One evidence-preserving lifecycle.

The workbench is designed to connect each document change to its source, evidence, decision, and resulting revision.

  1. 01 Original source Unchanged and identified
  2. 02 Extraction Format-aware outputs
  3. 03 Evidence-based diagnosis Findings cite document items
  4. 04 Explicit human decision Authority stays with people
  5. 05 Reversible refinement Attributable operations
  6. 06 Prepared revision Auditable output boundary
  7. 07 Corpus inspection and comparison Patterns across mixed formats

The runnable local path covers source capture, extraction observation, evidence-based diagnosis, explicit decisions, reversible transformations, prepared revisions, corpus inspection, read-only verification, and a loopback-only visual workbench.

One inspectable history

Build every capability on evidence.

Extraction, diagnosis, controlled revisions, static corpus comparison, and the local visual workbench use one inspectable evidence trail.

01 · Current foundation

Extract

Compare Docling and MarkItDown while retaining lossless canonical evidence and source identity.

02 · Current foundation

Diagnose

Record deterministic findings with evidence, stable identifiers, severity, provenance, and affected items.

03 · Available

Refine

Resolve one finding at a time, create immutable prepared revisions, and preserve reversible transformation history.

04 · Available

Compare

Inspect a mixed-format corpus through a static offline report with evidence links, grouped findings, extractor deltas, and revision histories.

05 · Unreleased source

Explore locally

Inspect explicit verified records in the bundled read-only browser interface. It binds only to 127.0.0.1, keeps no session state, and uses an internal HTTP bridge.

Trust and control

Preserve evidence. Keep people in control.

Extraction, diagnosis, decisions, and revisions stay inspectable. Evidence alone never grants authority to change a document.

Evidence stays inspectable

Retain the record.

Original sources, raw extraction artifacts, findings, decisions, transformations, histories, hashes, and revisions remain inspectable.

People retain authority

Require explicit decisions.

Diagnosis does not authorize mutation. Interpretive refinements require explicit human confirmation.

Authenticity limit: integrity checking does not establish authorship or authenticity.

Local by design

Run the implemented path locally.

The CLI publishes observations, diagnoses, explicit decisions, prepared revisions, and corpus reports. Separate read-only commands verify those records. One approval creates one successor revision.

One-time setup

uv sync --frozen --python 3.12
uv run docling-tools models download layout tableformer --output-dir .cache/docling/models

Usage after activating .venv

corpus observe fixtures/golden/policy-memo.pdf
corpus diagnose OBSERVATION_DIRECTORY
corpus draft-refinement DIAGNOSIS_DIRECTORY --finding FINDING_ID --base OBSERVATION_DIRECTORY --output decision.json
# Edit only the decision fields, then:
corpus resolve-refinement decision.json --diagnosis DIAGNOSIS_DIRECTORY --base OBSERVATION_DIRECTORY
corpus verify-refinement REFINEMENT_DIRECTORY --diagnosis DIAGNOSIS_DIRECTORY --base OBSERVATION_DIRECTORY
corpus inspect fixtures/corpus/golden-matrix.json
corpus verify-corpus CORPUS_DIRECTORY --spec fixtures/corpus/golden-matrix.json
corpus workbench RECORD_DIRECTORY --no-open

The project is distributed as source from its repository. It does not ship prebuilt binaries. After setup, activate .venv to run corpus directly.

Project boundary

Stop at a prepared revision.

The workbench ends when an inspectable prepared document revision is ready. Chunking, embeddings, indexing, retrieval, generation, and RAG evaluation remain outside the boundary.
