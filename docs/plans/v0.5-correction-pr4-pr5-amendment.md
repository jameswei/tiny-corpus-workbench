## Workbench interface

CLI and Webapp are equivalent learning interfaces over shared
application/domain services. Neither invokes the other. The Webapp interface
is internal to the bundled UI and has no public or cross-version compatibility
promise.

Delete the startup JSON payload. `corpus workbench` prints only its serving
address, and browser opening uses the Python URL value directly.

Delete all four versioned Workbench JSON Schemas, their catalog entries,
Workbench semantic dispatch, versioned API snapshots, and schema-reference
composition. Do not replace them with a parallel schema family. Small typed
structures or serializers may improve producer readability; focused
producer-consumer and UI tests own the interface.

Keep these read-only routes:

```text
GET or HEAD /api/workbench
GET or HEAD /api/records/{record_key}
GET or HEAD /api/artifacts/{artifact_key}
```

The projection contains only `session_id`, counts for records/top-level/
contained, and navigation records. A navigation record contains `record_key`,
`kind`, `status`, `run_id`, one `{name, value}` primary identity, `origin`,
and `artifact_count`. Primary identity is exact and ordered independently of
dictionary insertion: observation uses `observation_id`, diagnosis uses
`diagnosis_id`, refinement uses `draft_id`, and corpus uses `corpus_id`.
Remove runtime, provenance, schema identity, projection role, top-level edge
dumps, and unused manifest or containment descriptors.

A record detail contains `record_key`, `kind`, artifact-integrity state,
relationships, one artifacts list, and a kind-specific view. Relationships
contain relation, state, target kind and `{name, value}` identity, plus an
optional target record key. Artifact descriptors contain only opaque
`artifact_key`, role, media type, size, hash, and availability. The root
manifest is an item in the same artifacts list.

Compose views from existing admitted records, persisted domain data, and
verifier results:

- every compact source is exactly `{key, name, media_type, size, sha256}`;
  `name` may be null when the record stores only a logical key;
- observation: compact source, DoclingDocument `{name, version}` rendered by
  the UI, extractor `{name, version, status, upstream_status, error}`, and the
  exact ten comparison metrics, deltas, and normalized-equality result;
- diagnosis: compact source, subject/derivation states, finding total, and
  findings with exactly `finding_id`, `rule_id`, `rule_version`, `summary`,
  `severity`, `document_refs`, and `evidence`;
- refinement: compact source, human decision, diagnosis/base/derivation/
  reversibility states, transformations, and revision chain;
- corpus: corpus/snapshot/status/totals, member matrix, family/format/extractor
  aggregates, comparisons, finding/revision groups, revision summaries, and
  external-revision relationship state.

Remove fields the bundled UI does not consume. Do not copy persisted schemas
or their `$defs` into the API layer.

HTTP errors use the status code plus a sanitized `StableError`-shaped
`{code, message}` body. No error schema or duplicate status field remains.

## Trusted-local boundary

The server is a foreground, single-user learning tool bound to `127.0.0.1`.
It is not a public service and does not treat other local processes as hostile.

Keep loopback binding, read-only GET/HEAD routing, `404` for unknown routes or
keys, `405` for other methods, safe DOM text rendering, and no remote browser
requests. Do not add remote binding, mutation, upload, discovery, workflow
execution, auth, TLS, users, sessions, rate limiting, persistence, or a
frontend framework.

Remove custom Host/Origin validation, production security-header policy,
header/request budgets, symlink-race and inode-identity hardening specific to
Workbench serving, repeated physical-file rechecks, changed-artifact `409`,
and their adversarial test matrix. This does not weaken persisted-record
verification or corpus integrity.

At startup, build an in-memory map from opaque artifact keys to captured bytes
for two exact sets from explicitly admitted records:

1. every admitted root manifest; and
2. the existing source-safe listed-artifact allowlist produced by
   `_listed_descriptors`: observation extractor artifacts plus comparison,
   diagnosis/refinement listed artifacts, and corpus listed artifacts except
   the static report and stylesheet.

Do not broaden this to every persisted descriptor or to an original business
source. Every artifact key advertised in a detail must exist in this byte map.
A request key is never a filesystem path. Malformed or absent keys return
`404`; present keys return captured bytes as `text/plain`. Restarting the
Workbench refreshes changed files. A simple size threshold may remain only as
a UI safeguard.

## Validation and review

The Workbench checkpoint must prove:

- all four record kinds and incomplete states render using current domain data;
- the UI consumes only fields emitted by the producer;
- the serving address, three routes, `404`, `405`, GET/HEAD, artifact lookup,
  text rendering, loopback bind, and no-remote-request behavior work;
- no Workbench schema, catalog key, semantic dispatch, versioned snapshot,
  runtime/provenance field, schema `$ref`, temporary shim, or physical path
  remains;
- persisted record verification, corpus tamper detection, atomic publication,
  source immutability, and explicit human refinement approval remain green;
- focused Workbench tests, corpus tests, complete unit/integration/offline
  suites, fixture/tools/site/compile/portability checks, and diff hygiene pass.

One fresh reviewer audits the full
`0b4a0e0198887f82c618de002b5a58c69993ed1b..head` candidate against the
original plan plus this amendment. The review covers corpus correctness,
Workbench composition, and their interaction in one pass. Every navigation
identity, compact-source key, finding key, DoclingDocument display,
relationship key, and artifact key has exact producer-consumer coverage.
`PASS` requires zero findings. The correction-wide integration review remains
the final gate after all later correction tasks; it is not duplicated here.

## Acceptance and rollback

Accept only when the corpus schema reduction remains genuine, the Workbench
has no duplicate schema/compatibility system, API composition reuses domain
data without storage-schema coupling, the trusted-local server is small, and
all required behavior is green.

If the combined candidate cannot satisfy these conditions without another
scope expansion, stop before push and return to the owner. Because no
intermediate branch is merged, rollback is limited to the current task branch
and `main` remains at the last green correction checkpoint.
