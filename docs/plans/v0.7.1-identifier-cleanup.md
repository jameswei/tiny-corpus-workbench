# v0.7.1 — Diagnostic and Refinement Identifier Cleanup

## Summary

Release one source-only maintenance update that removes the redundant `TCW-` prefix from the 10 diagnostic rule IDs and 3 refiner IDs before v0.8 builds new browser lifecycle behavior.

This is one atomic naming refactor:

```text
TCW-D001 … TCW-D010 → D001 … D010
TCW-R001 … TCW-R003 → R001 … R003
```

Keep rule/refiner names, behavior, severity, versions, field names, and mappings unchanged. Use one implementation task, one semantic PR, and no separate documentation or closeout PR.

This is an unlisted maintenance release between roadmap v0.7 and v0.8. The identifier and no-migration decisions are owner-set; the touchpoint inventory and validation coverage are repository-derived.

## Contract changes

- Keep `rule_id`, `refiner_id`, `name`, and finding `summary` structurally unchanged.
- Update the identifier values everywhere they are machine-consumed: rulesets, findings, proposals, transformations, histories, corpus evidence, schemas, fixtures, reports, and Workbench projections.
- Preserve user-oriented names such as `NORMALIZABLE_WHITESPACE` and `WHITESPACE_NORMALIZATION`. Do not change the Workbench display hierarchy in this release.
- Update all identities naturally derived from rule/refiner values, including ruleset parameter hashes, diagnosis IDs, finding IDs, draft IDs, transformation IDs, revision IDs, and related corpus evidence.
- Treat pre-v0.7.1 generated records as unsupported current inputs. Document that users should delete old `build/` data and regenerate it; add no migration, compatibility adapter, alias, fallback, or dual-ID acceptance.
- Old `TCW-Dxxx` and `TCW-Rxxx` values must fail current schema or verification checks. Do not accept both spellings.
- Do not rename ruleset names, JSON Schema `$id` values, package names, CLI commands, or unrelated `TCW` text.
