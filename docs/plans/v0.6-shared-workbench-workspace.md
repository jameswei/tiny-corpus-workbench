## Summary

Change the Workbench from a frozen viewer that accepts record roots at startup
to a read-only Webapp that stays open around one fixed-layout workspace and
manually refreshes its records.

- `corpus workbench` uses `build/` by default. `--workspace PATH` overrides it.
- Remove the old `RECORD...` positional arguments. Do not retain two startup
  modes.
- The CLI remains the only workflow-execution interface in v0.6. Do not add
  uploads, jobs, or Web workflow actions.
- The Workbench remains a foreground process and stops with `Ctrl-C`. Do not
  add daemon or background-process management.
- Set the package version to `0.6.0`. Keep record `format_version` at `1`.
  Existing JSON Schemas and persisted record shapes do not change.
- Deliver through the v0.6.0 tag, GitHub Release, and release-status closeout.
  Tagging and release publication still require owner authorization for the
  exact accepted SHA.

## Interfaces and behavior

### CLI and workspace

The new interface is:

```text
corpus workbench [--workspace WORKSPACE] [--port PORT] [--no-open]
```

- `--workspace` defaults to `build`.
- Argparse rejects `corpus workbench RECORD...` with exit `2`.
- A missing workspace or missing family directories is an empty workspace. The
  Workbench does not create directories.
- A workspace that exists but is not a readable directory fails as an input
  error before the serving URL is printed.
- The default layout is:

```text
build/
├── inputs/                     # reserved for v0.7; v0.6 does not create or scan it
├── extraction-observatory/
├── evidence-based-diagnosis/
├── controlled-revisions/
└── corpus-inspection/
```

- Keep all producer CLI default output roots unchanged. They already publish
  into the four record-family directories under `build/`.
- For a custom workspace, the user uses existing `--output-root` options to
  publish into the corresponding family directory. Do not add `--workspace`
  to other CLI commands in v0.6.

### Record discovery

Each refresh recursively searches only these fixed family-directory patterns:

```text
extraction-observatory/**/manifest.json
evidence-based-diagnosis/**/diagnosis-manifest.json
controlled-revisions/**/refinement-manifest.json
corpus-inspection/**/corpus-manifest.json
```

- Sort candidates by workspace-relative POSIX path.
- Ignore any candidate whose path contains a `.staging-*` publication
  directory.
- Do not scan `inputs/`, other workspace directories, or paths outside the
  workspace.
- Admit a corpus only through its `corpus-manifest.json`; existing corpus
  descriptors continue to expand contained observations and diagnoses. Do not
  discover those contained records again as top-level records.
- Do not introduce new symlink, security, or filesystem edge-case policy.
  Candidate records continue through the existing admission, integrity,
  relationship, logical-copy, and artifact-capture behavior.
- Empty discovery builds a valid empty projection. Do not relax the existing
  explicit `admit_records([])` error contract.

### Refresh state

Introduce an application-level `WorkbenchState` that owns the workspace,
current successful immutable projection, and last refresh status.

- Startup creates an empty projection and then attempts one refresh.
- A refresh completes discovery, admission, verification, and candidate
  projection construction before replacing the current projection.
- Replace the current projection atomically only after complete success.
- A malformed record, integrity failure, logical-copy conflict, ambiguous
  relationship, or response-size failure rejects the whole refresh.
- On failure, keep the previous successful projection and captured artifact
  bytes. On initial failure, keep the empty projection.
- When one candidate can be identified, report its workspace-relative path and
  a sanitized reason. For an aggregate conflict, report a generic sanitized
  message without an absolute path.
- A later successful refresh clears the stored error.
- Disk changes do not affect captured bytes before refresh. A successful
  refresh switches to a new snapshot.

The internal `/api/workbench` projection adds:

```json
{
  "refresh": {
    "status": "READY",
    "message": null
  }
}
```

or:

```json
{
  "refresh": {
    "status": "FAILED",
    "message": "workspace-relative/path: sanitized reason"
  }
}
```

Keep existing `session_id`, counts, records, detail, and artifact meanings. Do
not add a JSON Schema.

### HTTP bridge

Add one internal operation:

```text
POST /api/workbench/refresh
```

- The request body must be empty.
- Success returns `204 No Content`.
- Failure returns `409` with the existing simple `{code,message}` error shape
  and code `WORKSPACE_REFRESH_FAILED`.
- A nonempty body returns `400 INVALID_REQUEST`.
- `GET` or `HEAD /api/workbench/refresh` returns `405` with `Allow: POST`.
- Other mutation methods and routes remain unavailable.
- Do not add Origin policy, authentication, CSRF handling, WebSocket, SSE, or
  a public API contract.
- Keep synchronous request processing in v0.6. The UI waits during refresh.
  Do not introduce the v0.7 job or concurrency model early.

### Browser behavior

- Add a `Refresh records` button in the Workbench header.
- Initial load renders the current projection and refresh status.
- An empty workspace explains that the user can publish a CLI record into the
  workspace and refresh.
- Disable the button during refresh and report progress through the existing
  `aria-live` region.
- After success, reload `/api/workbench`. Preserve the selected `record_key`
  when it remains present; otherwise select the first record or show the empty
  state.
- On failure, keep the current list and detail visible and show the refresh
  error.
- Do not add polling, filesystem watching, browser persistence, navigation to
  filesystem paths, or workflow-execution controls.
- Record, detail, and artifact views remain read-only.

  empty startup, invalid workspace, port, browser-open, and `Ctrl-C`.

  exclusion, `.staging-*` exclusion, deterministic ordering, and corpus

  method-specific `405`/`Allow`, and unknown-route `404`.

  selected-record preservation, and safe text-only DOM construction.
- Asset validation continues to reject remote resources, executable HTML,
  browser persistence, WebSocket, and EventSource.

### Integration scenarios

1. Start with an empty temporary workspace and receive `READY` with zero
   records.
2. While the server runs, publish a Markdown observation with the CLI into
   `WORKSPACE/extraction-observatory`; refresh and inspect it without restarting.
3. Add observation, diagnosis, approved/rejected refinement, and corpus records;
   refresh and verify all four kinds, relationships, and contained records.
4. After a successful projection, tamper with one artifact; refresh must fail
   and old captured bytes must remain readable. Restore or remove the damaged
   record and refresh successfully.
5. Use default `build/` for model-free observe plus a running Workbench refresh,
   with no output configuration.
6. Preserve current record/detail/artifact views, plain-text retrieval,
