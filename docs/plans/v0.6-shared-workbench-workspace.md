# v0.6 — Shared Workbench Workspace

## Outcome

v0.6 let the Local Visual Workbench discover the four fixed record families in
one default or custom fixed-layout workspace. Startup builds one verified,
immutable in-memory projection. A manual refresh builds a complete candidate
and replaces the accepted projection only after every candidate record passes
verification.

If refresh fails, the Workbench reports the error and retains the last good
record details and captured artifact bytes. This makes refresh transactional
and prevents a mixed old-and-new view.

## Rationale and boundaries

Workspace discovery removed the need to list individual record paths while
preserving verification and record ownership. CLI producers remain the only
execution surface. The browser remains a read-only inspection tool, and its
loopback HTTP routes remain an internal bridge rather than a public API.

The milestone did not add file watching, automatic refresh, uploads, jobs,
browser workflow execution, persistence, remote binding, authentication, a
hosted service, or downstream RAG work. It did not change persisted record
schemas or the source-to-prepared-revision boundary.

## Validation outcome

The released workflow verified default and custom workspace discovery,
deterministic ordering, all four record families, complete-candidate
verification, atomic snapshot replacement, failure retention, captured-byte
consistency, loopback-only serving, and unchanged CLI lifecycle behavior.
