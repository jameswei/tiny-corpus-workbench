# v0.9.3 — Project Entry Points

**Status:** This note describes the v0.9.3 source change. Use
[GitHub Releases](https://github.com/jameswei/tiny-corpus-workbench/releases)
for current publication availability.

v0.9.3 improves the public entry points for the learning-first project. It
does not change the document lifecycle, Workbench behavior, CLI, records, or
learning curriculum.

## Changes

- Rewrite the English README around project value, the document lifecycle,
  three learning interfaces, observable records, and the shortest practical
  path.
- Add a Simplified Chinese README with the same information architecture.
- Redesign the landing page as a complete single-page introduction to the
  project purpose, evidence model, lifecycle, interfaces, and outputs.
- Show the six preparation stages as connected cards on wide screens and as a
  vertical sequence on narrow screens.
- Use real links for navigation and calls to action.
- Load English and Simplified Chinese text from independent JSON locale
  resources through stable `data-i18n` keys.
- Keep one shared Workbench screenshot asset for both languages.
- Extend the static-site validator to check local scripts, locale parity,
  referenced locale keys, and the complete published file inventory.

## Compatibility and boundaries

The landing page now uses one project-owned local JavaScript file to load its
locale resources. It has no external runtime dependency. English remains in
the HTML as the readable fallback when JavaScript is unavailable.

This patch adds no public API, persisted schema, command, rule, refiner, or
hosted service. The project still starts with a raw document and ends with an
inspectable prepared revision. Chunking, embeddings, indexing, retrieval,
generation, and RAG evaluation remain downstream.
