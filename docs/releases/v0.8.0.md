# v0.8.0 — Interactive Document Lifecycle

**Status:** This note describes the v0.8.0 source change. Use
[GitHub Releases](https://github.com/jameswei/tiny-corpus-workbench/releases)
for current publication availability.

This source release completes the single-document preparation lifecycle in the
Local Visual Workbench.

## Highlights

- Start a guided model-free lifecycle or observe one supported local document.
- See that the workspace verified a record before lifecycle actions appear.
- Diagnose an eligible observation or approved prepared revision.
- Inspect named findings and supported D007/R002, D009/R001, and D010/R003
  refiner capabilities.
- Create a readable proposal preview without editing JSON.
- Approve or reject the proposal through an explicit browser action.
- Inspect immutable decision, transformation, revision, lineage, and reversal
  evidence.
- Continue through the unchanged CLI when preferred.

## State and authority

Each browser proposal belongs to its diagnosis context. Browsing another record
does not move or expose that proposal. A pending proposal does not lock record
navigation. The Workbench disables navigation only while a lifecycle request
is in progress.

Proposal panels and action tokens stay in process memory. Reload does not
discover drafts or restore panels. Restart invalidates the token and live
proposal context. The browser never replays a state-changing action.

Workbench-created drafts remain under `WORKSPACE/refinement-drafts/` after a
decision. They are not workspace records. This is current behavior, not a
cross-version location promise.

Diagnosis does not authorize mutation. A browser click supplies the explicit
human decision. Only `refinement-manifest.json.decision` is persisted decision
authority.

## Compatibility and boundaries

v0.8 changes no dependency, CLI argument, persisted record schema, or public
API. Its loopback HTTP routes and UI metadata remain internal to the bundled
interface.

The process-local action token blocks ordinary cross-origin forms. It is not
authentication and does not protect against local processes. The Workbench
remains loopback-only, trusted-local, single-user, and source-only. It provides
no hosted document-processing service.

current behavior and the
