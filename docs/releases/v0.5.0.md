# v0.5.0 — Local Visual Workbench

v0.5.0 adds a read-only, loopback-only browser workbench for explicit local
records. It also establishes one unified v0.5 schema baseline across
observation, diagnosis, refinement, corpus, verification, fixture, and
workbench artifacts.

## Highlights

- Inspect explicit observation, diagnosis, refinement, and corpus records in a
  local browser.
- Explore a frozen in-memory projection without record discovery or session
  persistence.
- Use closed, bounded JSON APIs and authorized plain-text artifact responses.
- Keep workflow execution and mutation in the existing CLI.
- Preserve source immutability, diagnosis authority limits, refinement
  decisions, lineage, forward derivation, and exact reversal.

The interface uses bundled HTML, CSS, and JavaScript. It needs no remote
runtime resource. The server binds only to `127.0.0.1` and enforces local
authority, origin, method, route, traversal, symbolic-link, and artifact
integrity checks.

## Schema compatibility

The current v0.5 release supports only v0.5 schemas.

Artifacts created by v0.1, v0.2, v0.3, or v0.4 are unsupported. v0.5 does not
migrate those artifacts. Regenerate records with v0.5 before you read, verify,
or inspect them.

Earlier Git tags preserve the historical implementations and their artifacts.
Schema versions are separate from package and build provenance. Supported v0.5
provenance tuples are explicit.

## Start locally

```bash
uv sync --frozen --python 3.12
uv run --frozen tcw observe fixtures/golden/policy-memo.md \
  --output-root /tmp/tcw-workbench-observations
uv run --frozen tcw workbench OBSERVATION_DIRECTORY --no-open
```

Open the URL from the startup JSON. Stop the server with `Ctrl-C`.

Read the [Local Visual Workbench guide](../local-visual-workbench.md) for record
admission, browser views, API routes, security behavior, and integrity limits.
