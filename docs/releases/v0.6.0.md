# v0.6.0 — Shared Workbench Workspace

**Status:** Published on 2026-07-30 as a
[source-only GitHub Release](https://github.com/jameswei/tiny-corpus-workbench/releases/tag/v0.6.0)
with no custom assets.

This repository release note describes the accepted v0.6 behavior. It does
not make a future cross-version compatibility promise.

## Highlights

- Keep the read-only Local Visual Workbench open around one fixed-layout
  workspace.
- Use `build/` by default or select an isolated workspace with `--workspace`.
- Publish records with the existing CLI workflows, then accept them with
  manual transactional refresh.
- Keep the last good in-memory snapshot when a complete refresh candidate
  fails verification.
- Preserve record details and captured artifact bytes until a successful
  refresh replaces the snapshot.

The Workbench remains a foreground process. Stop it with `Ctrl-C`.

## Breaking Workbench CLI change

The current interface is:

```bash
corpus workbench [--workspace WORKSPACE] [--port PORT] [--no-open]
```

The command no longer accepts positional record roots. This replacement is
intentionally breaking. Existing producer commands keep their default output
roots and existing `--output-root` options.

The default workspace is `build/`. The Workbench discovers records only under
these fixed record-family directories:

```text
extraction-observatory/
evidence-based-diagnosis/
controlled-revisions/
corpus-inspection/
```

A missing workspace or family directory is a valid empty workspace. The
Workbench does not create it.

## Refresh behavior

Startup and each manual refresh discover and verify the complete candidate.
The Workbench replaces its in-memory projection only after complete success.

On failure, the interface reports `FAILED` and keeps the last good snapshot.
Repair or remove the invalid candidate, then refresh again. A later successful
refresh reports `READY` and replaces the snapshot.

The Workbench does not watch the filesystem. A published record does not
appear until the user refreshes.

## Record compatibility

Persisted records keep `format_version` `1`. v0.6 changes no record JSON Schema
or persisted record shape.

Current format-version-1 records remain usable when they pass the current
verifiers. The project keeps one current format for each generated record
family. It provides no migration or future cross-version reader promise.
Earlier Git tags preserve historical implementations.

## Deployment and security limits

The Workbench uses bundled HTML, CSS, and JavaScript. It binds only to
`127.0.0.1` and makes no remote browser requests.

Its loopback HTTP routes are an internal bridge for the bundled interface.
They are not a public or stable API. Other local processes can reach a
loopback port, so the Workbench is not an authentication or access-control
boundary.

The repository is source-only. v0.6 does not promise prebuilt binaries, Docker
images, package- or container-registry delivery, a hosted service, or a public
API.

The browser remains read-only. It does not upload documents, run observation
or other lifecycle workflows, diagnose, refine, repair, or publish records.
Use the CLI for workflow execution.
