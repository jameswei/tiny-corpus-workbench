# v0.7.0 — Web Observation Workflow

**Status:** Source release prepared. The `v0.7.0` tag and GitHub Release are not
claimed by this document. GitHub Releases owns publication state.

This source release makes observation the first document workflow available in
the Local Visual Workbench.

## Highlights

- Start the Workbench from a new empty workspace.
- Observe the guided `policy-memo.md` fixture without Docling model files.
- Upload one `.docx`, `.md`, `.pdf`, or `.txt` document up to 32 MiB.
- Follow real stage-level progress without percentage estimates.
- Refresh the complete workspace after publication and select the new record.
- Keep published records immutable and uploaded source content out of the
  browser.

## Inputs, jobs, and records

The Workbench stores an accepted upload under
`WORKSPACE/inputs/SHA256/ORIGINAL_FILENAME`. It reuses matching bytes without
overwrite. The guided fixture remains repository-owned.

One background worker runs one observation at a time. The server keeps only the
latest job in memory. Process restart clears job state but retains accepted
inputs and published observations.

A completed job means the observation record was published. The record can
still report `SUCCESS`, `PARTIAL_SUCCESS`, or `FAILED` for its extractors. An
exception before publication fails the job.

## Refresh and inspection

After publication, the Workbench verifies the complete workspace candidate. A
successful refresh selects the new observation. A failed refresh keeps the
previous accepted projection and the newly published record on disk.

The browser shows uploaded-source metadata only. It does not expose an uploaded
original through an HTTP route. Literal retrieval remains available for
admitted plain-text record artifacts.

## Compatibility and boundaries

v0.7 changes no persisted record schema and adds no dependency. The CLI
observation contract remains unchanged.

The Workbench can run observation. Diagnosis, refinement, and corpus workflows
remain CLI operations. The internal loopback routes are not a public API or an
access-control boundary. The project remains source-only and provides no hosted
document-processing service.

Read the [Local Visual Workbench guide](../local-visual-workbench.md) for exact
behavior and the [v0.7 lesson](../../learning/v0.7-web-observation-workflow.md)
for a model-free browser exercise.
