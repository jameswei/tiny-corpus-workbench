# 演练完整生命周期

本练习把前面几课串在一起。工作台不是另一套流程，它是一个面向学习者
的界面，背后用的就是命令行同款的已发布记录。

## 学完这一课

拿一份文档，从头到尾走一遍证据-决策的完整路径。再拿一份无发现项
的文档做对比。最后搞清楚：页面刷新或服务器重启之后，哪些结果还在、
哪些会丢。

## 建一个临时练习区

在仓库根目录开一个全新的本地工作区：

~~~bash
LESSON_WORKSPACE="$(mktemp -d)"
corpus workbench --workspace "$LESSON_WORKSPACE" --no-open
~~~

打开打印出来的本地地址，练完在终端按 `Ctrl-C`。工作台只绑 `127.0.0.1`，
不是线上服务。

## 路径 A：走一遍受支持的修改

用引导文档 `whitespace-cleanup.md`，按顺序跑完各个阶段。

### 1. 观察

添加文档，等观察跑完。先读阶段说明，再找出：

- 捕获下来的来源元数据；
- 两个提取视图；
- 规范的 `DoclingDocument` 交接点；
- 比较结果。

先别急着想"要不要改"。观察这一步只发布了来源和提取结果的证据，
没别的。

### 2. 诊断

进入诊断阶段，运行。这份引导文档会产生 D009。逐一看过去：发现项
名称、稳定标识符、严重程度、受影响内容、证据。想弄清楚 D009 为什么
存在，就点开规则参考。

问一个精准的问题："这条规则识别了什么条件？"别把发现项放大成
"这文档不行"。

### 3. 修订

选 D009 对应的受支持修订操作，创建提议。看一遍可见的空白字符对比。
注意，提议是临时的——它展示了一种确定的修改会是什么样，但文档还没
真改。

选**批准**或**拒绝**，然后点**记录决定**。继续之前，读一下操作旁边
的说明——它解释了为什么决定必须持久化，不能只是"当前页面选了就选了"。

### 4. 看结果

批准了，就打开修订版。看看已准备修订版、应用对比、修订版历史都在
不在。原始来源和基础记录依然保留。

拒绝了，到修订阶段看已发布的决策证据。修订版正确标记为"不需要"——
因为没有已批准的修改可看。这不是"操作没做完"，这本身就是一条完整
的路径。

## 路径 B：对比无发现项

添加引导文档 `policy-memo.md`，运行诊断。没有固定规则命中。仔细读结果：

- 观察和诊断仍然发布了可查的记录。
- 这轮不需要修订和修订版。
- 结果没说文档"普遍正确"或"完整无缺"。

拿这条路径跟 D009 比。区别在于：有没有固定规则提供了可进一步审查的
受支持条件，而不是谁"通过"了、谁"没通过"。

## 有意识地去用工作台

主区域为当前阶段给出一个学习问题。检查器把相关细节放在手边，但不会
把每个阶段都变成平铺的 JSON 面板。

- 先看**摘要** —— 当前阶段的主要结果。
- 想知道凭什么，看**证据**。
- 需要检查具体文件时，再打开**产物**。

文档列表把练习记录和语料库记录分开。只有当命令行在工作台之外发布了
新记录时，才需要刷新工作区。

## 安全恢复

已发布的记录和决定在磁盘上不会丢。页面刷新或服务器重启后，重新读取
工作区就能恢复已发布状态。临时提议面板和没记录的决定不能保留——
重新创建提议，再做一次明确选择就好。

::: tip 记住
工作台教的是生命周期。命令行提供的是完整精确的控制。两者都守住
同一条线：证据归证据，决策归决策。
:::

现在可以随时回到前面任何一课，检查语料库，或者拿项目示例文件
带着一个具体问题重复某个阶段。
