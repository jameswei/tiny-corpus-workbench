# Local Visual Workbench

Suggested time: 30–45 minutes.

## Learning goals

After this lesson, you can:

- start the local Workbench for record inspection;
- inspect a verified record in the current workspace interface;
- inspect record relationships and verification states;
- state the local security and authority limits.

## Terms

A **record root** is a directory with one supported root manifest.

A **projection** is the in-memory view of admitted records.

An **artifact key** authorizes one admitted artifact response. It is not a
filesystem path.

## Exercise

Complete this one-time setup from the repository root:

```bash
uv sync --frozen --python 3.12
```

Activate `.venv` to use `corpus` directly. You can instead prefix a usage
command with `uv run`.

1. Create a model-free observation.

   ```bash
   corpus observe fixtures/golden/policy-memo.md \
     --output-root /tmp/corpus-v05-lesson/extraction-observatory
   ```

2. Start the Workbench with the lesson workspace.

   ```bash
   corpus workbench --workspace /tmp/corpus-v05-lesson --no-open
   ```

3. Open the printed URL in your local browser.

4. Select the observation record.

5. Inspect the source metadata and extractor comparison.

6. Retrieve one authorized plain-text artifact.

7. Stop the server with `Ctrl-C`.

## Check your understanding

1. Why does the Workbench verify records before it shows them?
2. Which operations can the browser workbench perform?
3. What does `MISSING` mean for a relationship?
4. Why is a loopback-only service not an authentication boundary?
5. What must you do with an old v0.4 artifact before admission?

## Safe experiments

- Start the workbench on another unused port.
- Publish a diagnosis and its observation under the lesson workspace.
- Copy a record, change one artifact byte, and confirm that refresh fails.
- Request an unknown route and inspect the structured error.

Use only copied records for tamper experiments. The workbench never repairs a
changed record. A failed refresh keeps the last accepted snapshot.

For a refinement, the Workbench derives the decision only from
`refinement-manifest.json.decision`. It lets you inspect proposal evidence,
but it does not edit a proposal or treat transformation state or `report.md`
as decision authority.

The original v0.5 release accepted positional record roots. The current CLI
replaces that startup mode with one fixed-layout workspace. Read the
[v0.6 lesson](v0.6-shared-workbench-workspace.md) to publish and refresh while
the Workbench stays open.

Read the [Local Visual Workbench guide](../docs/local-visual-workbench.md) for
the complete workspace, admission, API, security, and integrity limits.
