# Local Visual Workbench

Suggested time: 30–45 minutes.

## Learning goals

After this lesson, you can:

- start the read-only local workbench;
- explain why it accepts explicit record roots;
- inspect record relationships and verification states;
- state the local security and authority limits.

## Terms

A **record root** is a directory with one supported v0.5 root manifest.

A **projection** is the frozen, in-memory view of admitted records.

An **artifact key** authorizes one admitted artifact response. It is not a
filesystem path.

## Exercise

Complete this one-time setup from the repository root:

```bash
uv sync --frozen --python 3.12
```

Activate `.venv` to use `corpus` directly. You can instead prefix a usage
command with `uv run`.

1. Create a model-free observation.

   ```bash
   corpus observe fixtures/golden/policy-memo.md \
     --output-root /tmp/corpus-v05-lesson
   ```

2. Copy the parent directory of the printed `manifest` value.

3. Start the workbench with that directory.

   ```bash
   corpus workbench OBSERVATION_DIRECTORY --no-open
   ```

4. Open the printed URL in your local browser.

5. Select the observation record.

6. Inspect the source metadata and extractor comparison.

7. Retrieve one authorized plain-text artifact.

8. Stop the server with `Ctrl-C`.

## Check your understanding

1. Why does the command require explicit record roots?
2. Which operations can the browser workbench perform?
3. What does `MISSING` mean for a relationship?
4. Why is a loopback-only service not an authentication boundary?
5. What must you do with an old v0.4 artifact before admission?

## Safe experiments

- Start the workbench on another unused port.
- Supply a diagnosis together with its observation.
- Copy a record, change one artifact byte, and confirm that startup fails.
- Request an unknown route and inspect the structured error.

Use only copied records for tamper experiments. The workbench never repairs a
changed record.
