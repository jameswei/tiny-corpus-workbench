# Shared Workbench Workspace

Suggested time: 30–45 minutes.

## Learning goals

After this lesson, you can:

- start the Workbench on an empty workspace;
- publish a record while the Workbench stays open;
- accept a new verified snapshot with manual refresh;
- explain why a failed refresh keeps the last good snapshot;
- remove an invalid candidate and return to `READY`.

## Terms

A **workspace** contains four fixed record-family directories.

A **candidate** is the complete set of records found during one refresh.

A **snapshot** is one accepted in-memory view of a verified candidate.

## Before you start

Run this setup from a clean source checkout:

```bash
uv sync --frozen --python 3.12
```

Activate `.venv` to use `corpus` directly:

```bash
source .venv/bin/activate
```

This exercise uses Markdown. It does not need Docling model files.

Use two terminal windows. Run all commands from the repository root.

## Exercise

1. Create an isolated empty workspace in the first terminal.

   ```bash
   LESSON_WORKSPACE="$(mktemp -d /tmp/tcw-v06-lesson.XXXXXX)"
   printf '%s\n' "$LESSON_WORKSPACE"
   ```

2. Start the Workbench in the first terminal.

   ```bash
   corpus workbench --workspace "$LESSON_WORKSPACE" --no-open
   ```

   Keep this process in the foreground. Leave this terminal open.

3. Open the printed URL in your browser.

   The Workbench shows `READY` and zero records.

4. Copy the printed workspace path into the second terminal.

   ```bash
   LESSON_WORKSPACE=/tmp/tcw-v06-lesson.COPIED_SUFFIX
   ```

   Replace `COPIED_SUFFIX` with the suffix from the first terminal.

5. Publish one observation from the second terminal.

   ```bash
   corpus observe fixtures/golden/policy-memo.md \
     --output-root "$LESSON_WORKSPACE/extraction-observatory"
   ```

   The CLI publishes the record. The open Workbench does not change yet.

6. Select **Refresh records** in the browser.

   The Workbench accepts a new snapshot. It shows one observation.

7. Inspect the observation and one plain-text artifact.

   The browser reads captured evidence. It does not run extraction.

8. Add one invalid candidate from the second terminal.

   ```bash
   mkdir -p \
     "$LESSON_WORKSPACE/extraction-observatory/invalid-candidate"
   printf '{\n' > \
     "$LESSON_WORKSPACE/extraction-observatory/invalid-candidate/manifest.json"
   ```

   This candidate is separate from the valid observation.

9. Select **Refresh records** again.

   The refresh status changes to `FAILED`. The accepted observation stays
   visible because the complete candidate did not pass verification.

10. Remove the invalid candidate from the second terminal.

    ```bash
    rm \
      "$LESSON_WORKSPACE/extraction-observatory/invalid-candidate/manifest.json"
    rmdir \
      "$LESSON_WORKSPACE/extraction-observatory/invalid-candidate"
    ```

11. Select **Refresh records** again.

    The status returns to `READY`. The valid observation remains available.

12. Stop the Workbench in the first terminal with `Ctrl-C`.

The producer command kept its normal `--output-root` option. It did not get a
Workbench-specific `--workspace` option.

The same flow works with the default `build/` workspace. Start
`corpus workbench --no-open`, publish with the normal producer defaults, and
refresh manually.

## Check your understanding

1. Why does the open Workbench not change immediately after publication?
2. Why does one invalid candidate reject the complete refresh?
3. Which evidence stays available after a failed refresh?
4. Why does `READY` not mean that the browser changed a record?
5. Which interface runs observation and other lifecycle workflows?
6. Why is a loopback-only service not an authentication boundary?

## Summary

The Workbench stays open around one fixed-layout workspace.

The CLI publishes records. Manual refresh verifies the complete candidate
before it replaces the accepted snapshot.

A failed refresh reports the error and keeps the last good snapshot. Repair or
remove the invalid candidate, then refresh again.

The Workbench remains read-only. It does not upload documents, run workflows,
watch the filesystem, or repair records.

Read the [Local Visual Workbench guide](../docs/local-visual-workbench.md) for
the complete workspace, refresh, integrity, and security behavior.
